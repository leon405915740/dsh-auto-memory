# Agent 记忆管理（Agent Memory Management）

让 AI Agent 拥有结构化、不混乱的持久记忆，适用于**编程项目**与**办公任务**。核心一句话：**记记忆不是「堆日志」，而是「分层 + 唯一权威现状 + 按生命周期维护」。**

> 触发本 skill 的场景：新开项目需要让 Agent 记住上下文；发现 Agent 记混、自相矛盾、重复忘事；或用户要求「给 Agent 永久 / 持久记忆」「换电脑迁移项目记忆」「整理记忆」。

> 本 skill 与 dsh-auto-memory 插件协同：插件提供**存储、工具与自动执行**（memory_note 写入即三查裁决；每 7 天自动全层整理；语义查重/覆写留痕/软删留痕/History 蒸馏均已内建），本 skill 提供**判断标准**。层映射：Current State → 项目笔记 Current State 段（memory_note layer=state）；Constraints → Constraints 段（layer=constraint）；Lessons → Lessons 段（layer=lesson）；History → 每日日志 + 日期流水段（memory_log / layer=history）。

## 一、记忆分四层（只分不混）

每个项目维护一套记忆，严格分成四层，同一事实只出现在一层：

| 层                         | 作用                         | 更新方式                   | 权威性  |
| ------------------------- | -------------------------- | ---------------------- | ---- |
| **Current State（当前状态）**   | 现在是什么：目标、进度、当前配置 / 仓位 / 方案 | 每次**覆盖更新** + 时间戳       | 唯一权威 |
| **Constraints（硬约束 / 规则）** | 底线、铁律、当前生效的规则              | **增改留痕**（见 §3）         | 当前生效 |
| **Lessons（教训）**           | 犯过的错、学到的经验                 | **增改留痕**（见 §3）         | 当前有效 |
| **History（历史日志）**         | 每日决策、推理过程、被推翻的旧方案          | **追加为主 + 修正标注 + 蒸馏压缩** | 归档   |

判据：**一条信息只进一层**—— 现状进 Current State，规则进 Constraints，教训进 Lessons，推理 / 决策过程进 History。

## 二、记忆生命周期：四个动作（核心标准）

**任何记忆写入前，先裁决动作，绝不盲目追加。** 四个动作：`追加 / 覆写 / 合并去重 / 删除`。

| 动作                   | 何时用                                           | 判据口诀              |
| -------------------- | --------------------------------------------- | ----------------- |
| **追加 Append**        | 全新事实、新教训、新决策记录；与现有内容**既不同义也不矛盾**              | 这是新事 → 追加         |
| **覆写 Overwrite**     | 同一「事实实体」的取值 / 状态**发生变化或被推翻**（配置改了、目标变了、结论被纠正） | 旧事新值 → 覆写，旧值留痕    |
| **合并去重 Merge/Dedup** | 两条以上记忆表达**同一事实 / 同一规则**，只是措辞不同；或跨层重复          | 重复 → 合并，保留最全最新    |
| **删除 Delete**        | 事实性错误、已彻底无关、被用户明确作废、已被更高权威取代                  | 证伪 / 无关 / 作废 → 删除 |

### 详细判据

**覆写（Overwrite）**—— 当且仅当满足其一：

* 同一条事实的取值变化：如「Node 18」→「Node 22」、目标从 A 变为 B；
* 旧方案 / 旧结论被明确推翻（如用户否定了某个方向、实验证明某做法不成立）；
* 新信息是旧信息的**版本更新**（同一实体、新取值），而非**补充侧面**。
* **不是**覆写的情形：新信息只是补充一个不同的侧面（如「性能好」与「内存占用高」是两条不同事实）→ 追加。

**合并去重（Merge/Dedup）**—— 当且仅当：

* 归一化（去掉修饰词、时态后）核心语义等价；
* 同一条信息同时出现在多层（如进度既写在 Current State 又写进 History）。
* 处理：保留**最完整 + 最新**的一条，其余删除；在被删位置（或 History）标注「已并入」+ 保留 ID 指向，确保证据链不断。

**删除（Delete）**—— 当且仅当：

* 已证实与事实不符（事实性错误）；
* 已彻底过时且无历史价值（一次性临时决策、早已失效的配置）；
* 被用户明确作废；
* 已被更高权威来源取代（如当前状态已在别处统一维护）。
* 分级：**软删**（默认）→ 标注 `~~旧内容~~ 已于 YYYY-MM-DD 覆写/删除，原因：...`，内容留痕；**硬删** → 仅对垃圾信息 / 用户明示作废，彻底移除。

### 冲突裁决：写之前先三查

1. **查冲突**：新信息与现有记忆矛盾？→ 以新为准，**覆写**旧值，旧值标注留痕；
2. **查重复**：是否已有同义 / 近义内容？→ **合并去重**，不追加；
3. **查价值**：是「决策 / 约束 / 偏好 / 教训」吗？→ 不是则**丢弃**。

> 插件内建执行：`memory_note` 的 constraint/lesson 写入会自动做三查裁决（语义 Dice 查重 + 实体取值冲突检测），命中覆写/合并时自动留痕，你只需提供事实。

## 三、各层维护策略（升级版）

原来的「只增不改」改为「**增改留痕**」：能改、能删，但每次改动都留下变更记录，保证「为什么变成今天这样」的证据链不断。

| 层                 | 维护策略                  | 说明                                                    |
| ----------------- | --------------------- | ----------------------------------------------------- |
| **Current State** | 覆盖更新 + 删除过期项          | 唯一权威，直接覆写；已无关的旧项删除或归档                                 |
| **Constraints**   | 追加 + 覆写留痕 + 删除失效      | 新规则追加；规则变化（版本升级、被新约束取代）→ 覆写旧规则并标注变更原因与日期；已失效约束 → 删除留痕 |
| **Lessons**       | 追加 + 合并去重 + 修正 / 删除证伪 | 新教训追加；同义教训合并；被证伪的教训 → 标注修正或删除                         |
| **History**       | 追加为主 + 修正性标注 + 蒸馏压缩   | 正常追加；错误记录标注「已更正」；超龄过程细节蒸馏为结论摘要                     |

**证据链保证**：所有覆写 / 删除都遵循「留痕原则」—— 被替换的旧值要么在原位划线标注（~~旧~~ → 新），要么移入 History 归档。History 永不无痕抹除，只有「标注更正 / 合并 / 蒸馏压缩」。

## 四、记忆维护时机（Hygiene）

* **写时维护**：每次 brain-dump 写入前，先按 §2 三查裁决动作，再写入。默认动作是**追加**，只有命中判据才覆写 / 合并 / 删除。
* **定期维护**：每 **7 天**（插件 `maintainIntervalDays` 可配，0=关闭）自动做一次全层整理：
  1. 扫描四层，找出**重复** → 合并去重；
  2. 找出**过时**（取值已变化、约束已失效）→ 覆写或归档删除（软删留痕）；
  3. 找出**被证伪** → 标注 / 删除；
  4. History 超龄细节（`maintainDistillDays`，默认 30 天）→ **蒸馏压缩**为结论摘要，原始细节归档或清除噪音。
  * 也可手动触发：`memory_maintain(days=N)`。
* 记忆条目带**状态标记**：`[active]`（当前有效）/ `[superseded]`（已被覆写，保留证据链）/ 删除只对 `active` 生效；`superseded` 默认保留除非用户明确要求清理。

## 五、闭环三步：检索 → 锁定 → 写入

1. **开工检索**—— 按固定顺序读：`Current State → Constraints → 按需检索 History`。顺序不能乱，先知道现状和底线，再看历史。
2. **执行锁定**—— 全程把 Constraints 当不可偏离的底线；把目标和「为什么」写在**离执行最近的地方**（代码注释 / 提示词顶部 / 文档「硬约束」区），确保每次执行都读到。
3. **收工写入**—— 任务结束做一次 **brain-dump**：先按 §2 三查裁决，再只提炼「决策、约束、偏好、教训」四类重要信息，其余丢弃；覆盖 Current State，其余按生命周期规则写入对应层。

## 六、落地模板

使用 dsh-auto-memory 插件时的落点（集中式存储，自动迁移，换机不丢）：

- Current State → `memory_note(layer="state", content=...)`（覆盖 + 自动时间戳 + 长度护栏）
- Constraints → `memory_note(layer="constraint", content=...)`（写入自动三查裁决：追加/覆写留痕/合并去重）
- Lessons → `memory_note(layer="lesson", content=...)`（同上）
- History → `memory_log(note=...)`（append-only 每日日志）+ `memory_note(layer="history", ...)`（日期流水）

Current State 段骨架：

```markdown
## Current State(唯一权威,覆盖更新)
- 更新时间: YYYY-MM-DD
- 当前目标 / 配置 / 进度
```

Constraints/Lessons 条目状态标记：

```markdown
## Constraints(增改留痕)
- [active] 规则内容(当前生效)
- ~~旧规则~~ [superseded] 已于 YYYY-MM-DD 覆写为: 新规则;原因: ...
```

## 七、迁移说明

本 skill 随 dsh-auto-memory 插件发布（`@a9i5k4/dsh-auto-memory`，GitHub: Aik358/dsh-auto-memory），安装插件即自动获得并经 `ctx.skills.register()` 注册，无需单独迁移。记忆数据位于 `~/.dsh/memory/`（用户级）与 `~/.dsh/memory/workspaces/`（每个工作区一目录），跨电脑迁移时复制该目录即可。
